# IRIX 7 native interface is a capability/object model; the legacy ABI is a compat container

IRIX 7's native interface for new Rust programs is a capability/object model — per-process handle tables with rights, jobs, channels, VMAR/VMO memory objects, and ports for asynchronous completion — giving least privilege with no ambient authority. The legacy IRIX 6.5 ABI (o32/n32) is not a second implementation but a Starnix-style compat container that translates legacy syscalls into operations on those same objects, so files, memory and processes have one source of truth.

**Consequences**: the native side carries no ambient `/`, uid 0, or raw ioctl; legacy binaries get those reconstructed inside a bounded container over the capability model. `fork` is a copy-on-write VMAR/VMO clone, and `sproc` maps directly onto native threads sharing one address space — the identity trait in ADR-0013's neighbour. The object model is width-agnostic so a future 64-bit or CHERI-MIPS port does not touch it. This is the load-bearing choice that keeps IRIX 7 from being "another Linux or BSD": the capability substrate is the Fuchsia/seL4 lineage, with IRIX's identity layered on as first-class services.
