# Project Audit: 212013a

Date: 2026-10-05. Snapshot: `212013a`, with the implementation reviewed against
`b5171ed`. This report supersedes the earlier conversational progress summaries
as an assessment of the evidence, not as a replacement project specification.

## Method and limits

The review covered the public build scripts, GCC patch series, rig and oracle
drivers, smoke harness, hinv reference/substitution, runtime rebuild, tests,
ADRs and current GitHub issue bodies/comments. Independent domain reviews
were followed by host-side probes against the installed toolchain and retained
archives. A separate read-only inventory covered the private source tree.

No guest control commands, provisioning, source rebuilds, installed-prefix
changes, tracker edits, commits or pushes were performed during this audit.
Private SGI source text is deliberately not reproduced here. Promoted from the
scratch area on 2026-10-07.

"Confirmed" means demonstrated by code, artefact inspection or a bounded
probe. It does not mean that every prospective guest failure was executed.
Passing a small programme establishes that particular path, not general ABI
or library compatibility.

## Standards

### S1: P1, confirmed publication-policy conflict

`scripts/runtime/rebuild-libc.py:92-94` embeds a source-specific statement as
a repair matcher. Read-only comparison found an exact trimmed-line match in
the private tree's committed source. This conflicts with ADR-0001's explicit
"no tree excerpts" rule and the no-tree-text assurances in the compatibility
code/documentation. The expression is not reproduced here.

Remove the public source excerpt by recognising the construct generically or
deriving the matcher privately. Inspect already-published history before
claiming the repository is clean. This is a project-policy finding, not a
determination of copyright infringement or permission.

### S2: P1, confirmed stock-behaviour violation

`scripts/runtime/include/msgs/uxlibc.h:32-48` substitutes catalogue-key strings
for the default message-text macros consumed by `regerror()`. Private
comparison established that the actual generator emits plain default text.
The caller therefore receives a catalogue-like identifier rather than an
error explanation when catalogue lookup falls back. The lookup numbering
also differs from the private message source.

This contradicts the header's own explanation and `docs/runtime.md:130-134`,
and violates the stock-rebuild behaviour contract in `CONTEXT.md:7-8`.
Generate the headers privately from the existing message inputs; do not
guess identifiers or commit generated SGI message text.

### S3: P2, native-runtime reference is an evidence gap

ADR-0005 requires native headers, flags, object lists and link lines before
compiler substitution. The repository has a native hinv reference, but no
matching native libc build transcript/object manifest was located to support
`docs/runtime.md:50-52`'s "same objects MIPSpro built" assertion. Compilation
through a reconstructed selector and matching one hello are not that native
reference. Obtain it or record an explicit, bounded ADR exception.

### Provenance qualification

Pinned pdaxrom downloads match recorded hashes, and the series contains the
declared public diff material with GNU notices. That establishes origin
traceability, not blanket licence clearance of every additional contribution.
The original pdaxrom tree has no standalone repository licence. The oracle
documentation also records use of a locally modified MIPSpro driver with its
licence check removed; applicable permission was not established by this
audit. Neither point is a definitive legal conclusion.

## Spec and correctness

### C1: P1, the archive called libm is not stock libm

`scripts/runtime/rebuild-libc.py:707-729` archives the libc maths leaf as
`libm.a`. The retained 59-member archive exports neither public `sqrt` nor
`sin`, `cos`, `exp`, `log` or `pow`; its sqrt member exports internal helper
names. A fresh host-side cross link using an external `sqrt` reference fails.

`oracle/hello.c:15` calls `sqrt` with a constant argument, and the runtime
build enables optimisation at `rebuild-libc.py:741-747`. The retained hello
object references only `_gp_disp`, `printf` and `puts`; its maths result was
constant-folded. The static executable and printed output are real, but they
do not prove rebuilt libm or even an external maths call. Issue #9's broad
libm-completion claim is contradicted by the artefacts.

### C2: P1, mq_open entry points are lost

The K&R-definition repair at `rebuild-libc.py:89-91` interacts with existing
weak aliases through `compat.py:77-91,101-114`. The retained object defines
`__mq_open_impl`, leaves `_mq_open` undefined and defines neither public
`mq_open` nor `_mq_open`. The archive has no replacement definition. The
synthetic test checks replacement text without the surrounding source alias
machinery, so it misses the actual exported-symbol failure.

### C3: P1, a semantic AIO compiler definition is dropped

The makefile evaluator recovers `SUBDIR_COPTS=-D__AIO_52_COMPAT__`, but
`rebuild-libc.py:212-216` excludes that variable from the C flags. Private
inspection shows the definition controls AIO compatibility validation, not
just optimisation. Omission selects different behaviour, capable of rejecting
requests with `EINVAL`. The omission is confirmed; guest consequences were
not executed.

### C4: P1, archive order depends on worker completion

`rebuild-libc.py:690-691` collects completed tasks in nondeterministic order,
and `:705-728` passes that order to the archiver. This contradicts the
documented source-order preservation. The archive contains competing weak
syscall definitions and strong wrappers; retained timer members are reversed
relative to their manifest order. Archive extraction can satisfy a reference
from an earlier weak member without pulling the later wrapper. Ordering and
symbol competition are confirmed; resulting guest failures are inferred.

### C5: P1, n32 long double is ABI-incompatible

`patches/gcc-16.2/0002-irix-mips-target-macros.patch:469` carries an obsolete
`MIPS_TFMODE_FORMAT` hook. The installed compiler reports n32 mantissa/exponent
values `113/16384` and emits binary128, while the captured IRIX headers specify
double-double values `107/1024`. This changes values exchanged with SGI
objects/libraries. The same defect exists in the pdaxrom baseline; agreement
with that baseline does not establish the IRIX ABI. Calling the dead hook
harmless in `docs/toolchain.md:116-119` is incorrect.

### C6: P1, common-symbol alignment is discarded

`0003-irix-mips-codegen.patch:72-77` changes the final argument of
`mips_declare_common_object` to false. That argument controls emission of the
alignment operand, not symbol locality. A 64-byte-aligned tentative definition
under `-O2 -fcommon` becomes `.comm aligned_slot,64` without the required
alignment, while GCC folds its address modulo 64 to zero. A domain-review
link probe placed such a symbol at an address only 16-byte aligned.

### C7: P1, n32 sysroot substitution mixes captures

`0002-irix-mips-target-macros.patch:414-432,444-465` builds startfile/library
paths using the configured `TARGET_SYSTEM_ROOT`. A different command-line
`--sysroot` changes the linker's root but retains startfiles and ISA-specific
search paths from the original capture. Headers and runtime inputs can come
from different installations. A driver dry run confirmed the mixed paths.

### C8: P1, oracle login can address the sibling guest

`oracle.sh:95-98` supplies the isolated socket to its Python driver, but
`oracle-driver.py:104-108` calls `iris-ci login/boot` without propagating it.
The pinned CLI falls back to the default socket or an inherited environment.
A bounded mock confirmed the omitted socket. Standalone installer verification
has the same weakness, although provisioning itself supplies the environment.

### C9: P1, lifecycle helpers lack safe ownership and ordering

`stop-rig.sh:35-53` can ignore a failed quit and signal a saved PID after only
`kill -0`; a stale PID may identify another process. `provision-guest.sh:44-47`
unlinks backing files before stopping a running guest. Provisioning, oracle
work and lifecycle operations do not acquire the shared transaction lock.
Concurrent operations can interleave serial/scratch access or create multiple
emulators. These unsafe control flows are confirmed; no signals or destructive
operations were exercised.

### C10: P1, test transactions have false-pass paths

`smoke.sh:203-226` suppresses retrieval errors and records, but never rejects,
a non-zero transaction status once stdout/status files exist. A failed transport
after the programme writes matching output and status zero can still pass.

`rebuild-libc.py:556-570` additionally reuses host result files without clearing
them and ignores retrieval failures, permitting stale evidence. Its ELF proof
at `:794-797` ignores readelf's return code: empty failure output passes the
absence-of-INTERP/NEEDED test. Retained binaries were independently inspected
and really have the stated ELF shapes; that does not repair the acceptance
logic or establish that historical runs took the false-pass branches.

### C11: P2, the smake evaluator is not a sound driver foundation yet

`smake.py:40` misses real unquoted includes and silently skips their definitions.
Synthetic probes also reproduced immediate expansion of `=` forward references
at `:374-384`, failure to expand variables inside quoted conditions at
`:187-193`, and substitution across the entire string rather than each word
at `:110-116`. The chosen direction remains to extend this evaluator, but
semantic compatibility must precede target/recipe execution. Repairing one
condition parser defect did not change the current o32 source selection;
that does not validate other leaves or ABI variants.

### C12: P2, C++ is needed and its port has in-scope build blockers

The private tree has 511 C++ source-suffix candidates after obvious fixtures
and m4-to-C inputs are excluded. Make rules identify installed components
including fam, mediad, libfam, nfsunhang and the SNMP agent. Package selection
can narrow scope, but "possibly no C++ at all" is not a sound default for the
full stock rebuild.

`0006-libstdcxx-irix-os-layer.patch:550-574,617-651` uses removed namespace
macros and lacks `ctype_base::blank`, required by modern locale headers.
Bounded parsing exposed these errors. No working o32/n32 C++ installation was
found. The n64 configure failure does not prove those libraries already built;
issue #22's assertion that they did is unsupported.

### C13: P2, hosted stdint inclusion fails

`0001-irix-target-config-and-startfiles.patch:62-67` selects a system-header
wrapper for IRIX 6.5. The required capture has no system `stdint.h`, so a
fresh hosted inclusion fails at `include_next` for both supported ABIs.
GCC's freestanding integer-type header exists, but normal hosted compilation
does not use it successfully.

### C14: P2, the recursive gthread fallback loses recursion

`0004-irix-libgcc-and-runtime.patch:105-116` removes recursive mutex attributes
without providing an equivalent fallback. The target headers lack the static
recursive initialisers, selecting this branch. A bounded host probe initialised
and locked the mutex, then got `EBUSY` on a second try-lock. Deadlock in IRIX
recursive consumers is inferred, not guest-executed. Removed equality/yield
wrappers and exception/thread behaviour also need target tests.

### C15: P2, authoritative acceptance records drift from the goal

The parent still requires a static hello as the first proof despite ADR-0006,
describes every ABI as ELF32 and still calls the #10 make choice outstanding.
ADR-0007 and `docs/runtime.md:185-188` invent a loader-rebuild milestone despite
#1 explicitly excluding rld reimplementation. #14 allows a documented exception
list to substitute for a completed build without an approval boundary. Critical
in-scope libraries must not disappear into that list while the project is still
called a complete stock rebuild. Native parent/sub-issue links/task lists are
also missing, despite the documented frontier query depending on them.

### C16: P2, resume state omits source identity

`build-toolchain.sh:247-249,290-300,403-406` records patch filenames and configure
arguments but not complete source/patch identity. Same-named patch changes can
reuse an old installed compiler. Reusing a work directory for another GCC
release can reuse its previously configured source. `flake.nix:74-75` always
supplies the 16.2 work directory, undermining version-separated defaults.

### C17: P2, installation markers can certify the wrong state

Installer success detection discards some scan/selection/quit errors and gives
success precedence over errors in a go transcript. Stored evidence includes an
incompatible-subsystems error followed by "install: ok". Existing release data
are useful, but whether historical conflicts remain is unverified.

A missing disk can be replaced with a blank one while old verify markers cause
installation to be skipped. Markers are timestamp-only and non-atomic; retries
also assume particular console prompts. Bind state to disk/config generations
and actual postconditions instead of marker existence.

### C18: P2, recapture destroys the previous baseline

`oracle.sh:168-178` deletes previous oracle/sysroot artefacts before replacement
compilation and transfer succeed. Failure loses the known baseline and can
disrupt host builds using it. Publish complete capture generations atomically.
The extracted-tree regular-file checksum also omits symlink targets/types.

### C19: P2, emulator binary caching does not attest the source pin

`build-iris.sh:60-66` checks out the chosen commit and accepts existing binaries
without a build identity. A changed pin can retain old binaries. Forced checkout
also discards tracked local emulator changes without requiring the script's force
option. Current inspected source matches the pin; cache correctness does not
follow from that particular successful state.

### C20: P2, inherited formatting fixes change semantics

`0006-libstdcxx-irix-os-layer.patch:988-997` makes special floating-value handling
always return nullopt without disabling the formatting paths that require it.
NaN/infinity/zero handling is not proven. The wide-time-format workaround at
`:27` casts a wide string to bytes instead of converting it; big-endian ASCII
wide formats begin with a zero byte. Source-level defects are confirmed; target
execution consequences remain unverified.

### C21: P2, hinv input equivalence is not sealed

`hinv-reference.sh:196-218` records revision/status but not all staged input
hashes, and `hinv-gcc.sh:203-215` does not enforce identity with that capture.
Native and cross builds also use different header sets, some substantively
different. The recorded default n32 output match is real; attribution of every
possible divergence solely to the compiler is too strong.

## What is genuinely demonstrated

The GCC 16.2 source archive's SHA-512 matches the official GCC release checksum
list. GNU's release timeline confirms 16.2 and its release date; installed tools
identify consistently. Cryptographic release signatures were not independently
validated. Cached pdaxrom diffs match their pinned hashes.

Retained records substantiate a fresh 6.5.7m guest, MIPSpro 7.30/CEE 7.4 and
captured development files; simple dynamic o32/n32 programmes; matching native
and GCC default hinv output; and a truly static o32 startup/formatting hello
linked with rebuilt libc objects. Host link probes also selected captured
startfiles/libraries correctly for the configured root.

These are substantial bring-up results. They are not evidence of faithful
replacement libc/libm, broad IRIX ABI compatibility, working C++, firmware,
kernel boot, complete installation media or native bootstrap.

The broad private inventory did not find a complete standalone stock libm or
user-space rld executable build. It did find libc maths support, some genuine
libm-derived fragments, loader bootstrap code and firmware/diagnostic loaders.
Absence in this supplied tree does not establish historical binary-only
distribution or permission to omit a required product.

## Verification run

All seven directly executed Python test files passed: 4 installer, 14 oracle,
10 hinv, 36 smake, 24 compatibility, 17 runtime-driver and 9 smoke tests,
**114 total**. Bash syntax checks passed for all shell scripts.

Generic unittest discovery using the existing hyphenated test filenames ran
zero tests. The direct commands were therefore used; no discovery success was
counted as coverage. Current tests largely cover synthetic transforms and local
argument validation, not the high-risk guest transactions or ABI boundaries.

Fresh host-side probes reproduced missing public maths linkage, missing
mq_open symbols, constant-folded hello maths, n32 long-double limits, hosted
stdint failure, lost common alignment, omitted oracle socket propagation and
smake semantic failures. No new guest run or clean full rebuild was attempted.

Standards: 3 findings, including 2 confirmed policy/contract failures.
Spec/correctness: 21 findings; the broad libm milestone and n32 ABI claims are
the most consequential demonstrated overclaims.
