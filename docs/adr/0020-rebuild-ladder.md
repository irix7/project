# The rebuild ladder is three stages, mapped one-to-one onto the board columns

The rebuild runs as three successive stages, each owning one group of board columns. The **stock rebuild** (`IRIX cc`/`IRIX run`) reproduces IRIX 6.5.7m in the guest with IRIX's own tools, changing no behaviour — the reference-first ground truth of ADR-0005. The **modernised tree** (`GCC cc`/`GCC run`) rebuilds that same OS with the new GCC outside the guest, still changing no behaviour, with GCC-enabling change carried on a branch of the private source tree `irix7/irix6` (build-side translation being an interim, non-policy path). **IRIX 7** (`Rust`) is the GPL-3.0 Rust reimplementation, the end goal. The earlier "modernised fork" name for the middle stage is retired: it was neither a fork nor a new OS version, but IRIX 6.5 made buildable by a modern compiler.

**Considered Options**: the old framing — stock rebuild = the IRIX *and* GCC passes, modernised fork = a later deliverable that changed behaviour to make a new IRIX-derived OS — rejected because it mislabelled the GCC pass as part of the stock rebuild and described a behaviour-preserving IRIX 6.5 as a new OS version.

**Consequences**: the board columns map directly to stages (`IRIX cc`/`IRIX run` stock, `GCC cc`/`GCC run` modernised tree, `Rust` IRIX 7). The old "never edit the tree" rule is dropped — its ADR-0005 citation was wrong — and GCC-enabling change lives on the modernised tree branch. The stream-translation tooling (`scripts/runtime/compat.py`) and the flag table (`docs/hinv-gcc.md`) that kept the tree stock are interim, not the direction: they stay while the libc and hinv proofs run, and are re-homed into the branch. Publication is unaffected — both lower stages stay private (ADR-0001); only IRIX 7 is published clean-room (ADR-0009).
